= Lab: Configure and Manage Device Fleets

_Estimated reading time: *{time_estimate} minutes*._

Objective::

Configure multiple device fleets and assign devices to them using fleet-level configurations.

Describe requirements, such as customer portal accounts, Red Hat Developer free sub, already configured machines, access to container registries, etc.

High-level summary of what you will perform in this lab, but more detailed than the objective.

2. Create a device fleet, using the web UI.
The process is very similar to editting a device configuration, if you remember the activity from the first course.
+
You will create a fleet with a device template that sets two configuration files, using the inline configuration provider: A pre-login banner (an "issue" message), and a lifecycle hook that enables login using the serial console.

.. On your _development machine_, start a web browser and open `\https://servera.lab.example.com`.
Log in on Edge Manager as `student` using the `student` password.
On the left pane, click menu:Fleets[].
It should display a page which states "No fleets yet".

.. Click menu:Create fleet[]. 
Name your new fleet as `store` and, under *Device selector*, click on menu:Add label[].
Type `location=store` as the device selector, and press kbd:[Tab] to leave the text box. 
Ignore the warning that "There are no devices matching these labels" and click menu:Next[].

.. Under *Host configuration (files)*, click menu:Add configuration[] and type `store` on the *Source name* field. 
Select `Inline configuration` as the *Source type* field.

.. Under *File 1*, type `/etc/issue.d/warning.issue` as the *File path* field, and type the following on the *Content* field:
+
[source,console,subs="verbatim,quotes"]
--
This is managed device {{ .metadata.labels.alias }}
Access by non-authorized personnel is strictly forbidden.
--
+
Also ensure that there is a blank line at the end of the multi-line text box.

.. Scroll down and click menu:Add file[] to create *File 2*.
Type `/etc/flightctl/hooks.d/afterupdating/enable-serial-console.yaml` as the *File path* field, and type the following on the *Content* field:
+
[source,console,subs="verbatim,quotes"]
--
- run: /usr/bin/systemctl enable serial-getty@ttyS0.service --now
--

.. Click menu:Next[] until you reach the end of the *Create fleet* assistant and click menu:Create fleet[].
You should get a details page for a fleet in the `Valid` state and with no devices.

3. Alter the labels on the first managed device so it joins the fleet and verify it got the fleet configuration.

.. Switch to a terminal and attempt to open the serial console of your local VM.
It does not display a log in prompt, no matter which keys you press.
Your only alternative is dettaching from the VM console using kbd:[Ctrl+\]].
+
[source,console,subs="verbatim,quotes"]
--
$ *virsh console edge-1*
Connected to domain 'edge-1'
Escape character is ^] (Ctrl + ])
--

.. Back to your web browser, click menu:Devices[] on the left pane.
Then click on the menu icon (three vertical dots) for the `edge-1` managed device and select menu:Edit device configurations[].

.. Click on menu:Add label[] and type `location=store` on the text box.
Press kbd:[Tab] to close the text box and notice that the page displays a green check mark under *Fleet name*, acknowledging that the new label makes the device a member of the `store` fleet.

.. Click menu:Next[] until you reach the last page of the assistant, and click menu:save[].

.. Scroll down and notice that the *Update status* is `Out-of-date`.
Wait until it changes to `Up-to-date`.

.. Switch to a terminal and attempt again to open a terminal.
You may have to press kbd:[Enter] a few times to get a log in prompt.
After you get the prompt, press kbd:[Ctrl+D] to reset the log in process and view the banner messages.
+
You should see the standard banner from Edge Manager, which displays a QR code used to enroll or manage the device, and the warning that the fleet configuration added.
+
You do not need to log in.
You can press kbd:[Ctrl+\]] to dettach from the virtual console, after confirming the warning banner is displayed by the device.
