Lab: Deploy Applications to a Fleet

Estimated reading time: 5 minutes.

Objective

Deploy a containerized application to a device fleet and observe its rollout and operation.

Not started yet.

Before you begin

Describe requirements, such as customer portal accounts, Red Hat Developer free sub, already configured machines, access to container registries, etc.

Instructions

High-level summary of what you will perform in this lab, but more detailed than the objective.

The classroom environment has an issue which requires setting SELinux to permissive mode. This is something Red Hat do NOT advises doing to any production system, including developer machines and CI/CD servers.

On your development machine, perform the following before you attempt any lab of this course.

$ sudo setenforce Permissive

Note tat SELinux is still in enforcing mode on your server machine and also on all test VMs which stand in for managed devices. Only your development machine needs SELinux set to permissive mode.

  2. Build and publish a bootc container image which includes a container runtime.

    Remember that the enrollment image, which you used at the beggining of this course, provided only a mininum RHEL system with the Edge Manager agent.

    1. Create a temporary working directory, and copy example files to it.

      $ mkdir temp-managedapp
$ cd temp-managedapp
$ cp -r ../rhde-rhem-samples/managedapp/* .

    2. Review the containerfile. It adds the container-tools meta-package, which includes Podman, and also the qemu-guest-agent, which should solve clock skew issues of local VMs.

      $ cat Containerfile
FROM registry.redhat.io/rhel9/rhel-bootc:9.6
# To use the upstream packages:
#RUN dnf -y config-manager --add-repo https://rpm.flightctl.io/flightctl-epel.repo && \
#    dnf -y install flightctl-agent-1.0.2 && \
# To use local copies of the packages:
ADD rpms /tmp
RUN dnf -y install /tmp/flightctl*.rpm && \
    dnf -y install container-tools qemu-guest-agent && \
    dnf clean all && \
    systemctl enable flightctl-agent && \
    systemctl enable qemu-guest-agent && \
    systemctl mask bootc-fetch-apply-updates.timer
ADD domain.crt /etc/pki/ca-trust/source/anchors/
RUN update-ca-trust

    3. Copy from the working directory of the enrollment image some auxiliary files which you neeed to include in your bootc container image, such as the private registry CAs and SSH keys.

      $ cp ../temp-enroll/domain.crt .
$ cp ../temp-enroll/edge-key.pub .
$ cp -r ../temp-enroll/rpms .

  4. Create a fleet which uses the new bootc container and also defines a single-container application.

    1. Review the fleet manifest, which uses all three configuration providers taught in this course series, just to show you can mix and match them at your convenience.

      $ cat frontend.yaml
apiVersion: flightctl.io/v1beta1
kind: Fleet
metadata:
  name: frontend
spec:
  selector:
    matchLabels:
      role: frontend
  template:
    spec:
      os:
        image: registry.lab.example.com:5000/containerhost:v1.0
      config:
      - inline:
        - content: |
            REPLACE_WITH_OSTREE_AUTH_JSON
          path: /etc/ostree/auth.json
        name: bootc-registry-auth
      - inline:
        - content: |
            REPLACE_WITH_ROOT_AUTH_JSON
          path: /root/.config/containers/auth.json
        name: app-registry-auth
      - gitRef:
          path: /managedapp/config
          repository: webapp
          targetRevision: main
        name: webapp
      applications:
      - appType: container
        envVars: {}
        image: registry.lab.example.com:5000/ubi9/httpd-24:latest
        name: httpd
        ports:
        - 80:8080
        volumes:
        - image:
            reference: registry.lab.example.com:5000/webappvol:v1.0
          mount:
            path: /var/www
          name: html

    2. Create an authentication file for the private registry, and add it to the fleet configuration. Notice it must be added in two places, because the container runtime and the bootc subsystems do NOT share the registry authentication files. course series, just to show you can mix and match them at your convenience.

      $ podman login --authfile auth.json -u student -p redhat registry.lab.example.com:5000
Login Succeeded!
$ AUTH_JSON=$( jq -c . auth.json )
$ sed -i "s|REPLACE_WITH_OSTREE_AUTH_JSON|$AUTH_JSON|" frontend.yaml
$ sed -i "s|REPLACE_WITH_ROOT_AUTH_JSON|$AUTH_JSON|" frontend.yaml

    3. Review your fleet manifest and ensure it does not contains any REPLACE markers anymore.

    4. Review the repository manifest, which defines the webapp git repository referenced by the frontend fleet. We provide this here just as an example of using configuration files from Git from the Edge Manager CLI.

      $ cat webapp.yaml
apiVersion: flightctl.io/v1beta1
kind: Repository
metadata:
  name: webapp-repo
spec:
  type: git
  url: https://github.com/RedHatQuickCourses/rhde-rhem-samples.git

    5. Apply the manifests to your Edge Manager server.

      The status of the fleet may be Unknown for a while, while Edge Manager fetches the configation files from the Git repository. 
      $ flightctl apply -f webapp.yaml
webapp.yaml: applying repository/webapp: 201 Created
$ flightctl apply -f frontend.yaml
frontend.yaml: applying fleet/frontend: 201 Created
$ flightctl get fleet frontend
NAME            OWNER   SELECTOR        VALID
frontend        <none>  role=frontend   True
