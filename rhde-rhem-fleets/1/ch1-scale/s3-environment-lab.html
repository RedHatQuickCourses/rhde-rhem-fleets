Lab: Prepare the Classroom Environment

Estimated reading time: 23 minutes.

Objective

Set up and configure the classroom environment for practicing Red Hat Edge Manager fleet management.

Before you begin

You need a customer portal account with access to a Red Hat Enterprise Linux (RHEL) subscription. It could be a Red Hat Developer program free subscription, if you use the upstream packages from the Flight Control project.

Be aware that, as time passes, there might be significant differences between newer upstream releases and the supported Red Hat product releases.
The GA release of Edge Manager requires either a Red Hat Device Edge or RHEL with Edge Manager subscription and it is NOT included with the developer program individual subscription.

You need a development machine running RHEL, to which you have unrestricted sudo access, and enough capacity to run a few local VMs.

You also need a server machine running RHEL, to which you also have unrestricted sudo access.

Both your development machine and server machine require internet access to download RPM packages and container images.

If you are using the course classroom, your development machine is the workstation VM. Log in as the user student with password student. From that machine, you may start SSH sessions to the servera VM, which is your server machine, using the same user. Alternatively, you can open a shell or a console directly on the servera VM.

Instructions

You will verify that Edge Manager is installed and running on your server machine; that you can log in to Edge Manager from your development machine; and also that you have all files required to provision and enroll new managed devices, such as: a custom bootc container image, SSH keys, and a custom installation ISO.

All that should be already available, if you are continuing straight from the first course without deleting and creating a new classroom environment, and you would skip most steps in this lab. In that case, this lab also provides some cleaning instructions, so you are not impacted by leftovers from the first course.

If you are starting from a new classroom environment, this lab provides step-by-step instructions to prepare all the necessary prerequisites for this course, so you do not have to return to the first course.

It should be possible to adapt the instructions in this course to any environment where you can install RPM packages, run Podman containers, and create VMs using libvirt. With a bit more effort, you could run everything on a Windows or MacOS workstation, using a single large VM running RHEL and nested virtualization, or a few smaller VMs, but this course does NOT provide instructions for doing so.

This course was tested using a Red Hat Learning Environment (ROL) classroom which was originally created for another quick course series. There was no customization for the specific needs of Edge Manager, and there was no attempt at providing all requirements to install Edge Manager in disconnected mode.

Some of the requirements of Edge Manager can be satisfied by the existing RPM package and container image mirrors in the ROL classroom, but some of them require internet access, a valid Red Hat login, and Red Hat subscription entitlements.

If this is your first time using a ROL classroom, please refer to the previous course for an introduction to the classroom environment and for more detail about prerequisite tasks such as: installing and configuring Red Hat Edge Manager, and enrolling managed devices.

The classroom environment has an issue which requires setting SELinux to permissive mode. This is something Red Hat does NOT advise doing to any production system, including developer machines and CI/CD servers.

On your development machine, perform the following before you attempt any lab in this course.

$ sudo setenforce Permissive

Note that SELinux is still in enforcing mode on your server machine and also on all test VMs which stand in for managed devices. Only your development machine needs SELinux set to permissive mode.

  6. Configure users for the Edge Manager services, on the PAM issuer container.

    1. Verify that you can log in to Edge Manager, from your development machine, as a regular user and also as an administrator. If you do, you can skip to step 7.

      If you see the prompt "Use insecure connections?", answer N and let the log in attempt fail. 
      $ flightctl login -u student -p student https://servera.lab.example.com:3443
Auto-selected organization: 00000000-0000-0000-0000-000000000000 Default
Login successful.
$ flightctl login -u admin -p redhat https://servera.lab.example.com:3443
Auto-selected organization: 00000000-0000-0000-0000-000000000000 Default
Login successful.

    2. If you cannot log in, switch to your server machine and create groups which correspond to the admin, operator, and viewer roles.

      $ sudo podman exec -i flightctl-pam-issuer groupadd flightctl-admin
$ sudo podman exec -i flightctl-pam-issuer groupadd flightctl-operator
$ sudo podman exec -i flightctl-pam-issuer groupadd flightctl-viewer

    3. Create a user named student and grant it the operator role.

      $ sudo podman exec flightctl-pam-issuer adduser student
$ sudo podman exec -i flightctl-pam-issuer sh -c 'echo "student:student" | chpasswd'
$ sudo podman exec -i flightctl-pam-issuer usermod -aG flightctl-operator student

    4. Create a user named admin and grant it the admin role.

      $ sudo podman exec flightctl-pam-issuer adduser admin
$ sudo podman exec -i flightctl-pam-issuer sh -c 'echo "admin:redhat" | chpasswd'
$ sudo podman exec -i flightctl-pam-issuer usermod -aG flightctl-admin admin

    5. Verify you have the required users and groups on the PAM issuer container.

      $ sudo podman exec -i flightctl-pam-issuer groups student
student : student flightctl-operator
$ sudo podman exec -i flightctl-pam-issuer groups admin
admin : admin flightctl-admin

    6. Switch to your development machine and copy the self-signed certificate of the Edge Manager server and add it to the system’s trusted CA set.

      $ scp servera:/etc/flightctl/pki/ca-bundle.crt ~
ca-bundle.crt             100% 1222   128.6KB/s   00:00
$ sudo cp ca-bundle.crt /etc/pki/ca-trust/source/anchors/
$ sudo update-ca-trust extract

    7. Verify that you can now log in to the Edge Manager server.

      $ flightctl login -u admin -p redhat https://servera.lab.example.com:3443
Auto-selected organization: 00000000-0000-0000-0000-000000000000 Default
