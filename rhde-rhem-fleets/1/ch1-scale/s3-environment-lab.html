Lab: Prepare the Classroom Environment

Estimated reading time: 5 minutes.

Objective

Set up and configure the classroom environment for practicing Red Hat Edge Manager fleet management.

Not started yet.

Before you begin

You need a customer portal account with access to a Red Hat Enterprise Linux (RHEL) subscription. It could be a Red Hat Developer program free subscription, if you use the upstream packages from the Flight Control project.

Be aware that, as time passes, there might be significant differences between newer upstream releases and the supported Red Hat product releases.
The GA release of Edge Manager requires either a Red Hat Device Edge or RHEL with Edge Manager subscription and it is NOT included with the developer program individual subscription.

You need a development machine running RHEL, to which you have unrestricted sudo access, and enough capacity to run a few local VMs.

You also need a server machine running RHEL, to which you also have unrestricted sudo access.

Both your development machine and server machine require internet access to download RPM packages and container images.

If you are using the course classroom, your development machine is the workstation VM. Log in as the user student with password student. From that machine, you may start SSH sessions to the servera VM, which is your server machine, using the same user. Alternatively, you can open a shell or a console directly on the servera VM.

Instructions

You can adapt the instructions in this course to any environment where you can install RPM packages, run Podman containers, and create VMs using libvirt. With a bit more effort, you could run everything on a Windows or MacOS workstation, using a single large VM running RHEL and nested virtualization, or a few smaller VMs, but this course does NOT provide instructions for doing so.

This course was tested using a Red Hat Learning Environment (ROL) classroom which was originally created for another quick course series. There was no customization for the specific needs of Edge Manager, and there was no attempt at providing all requirements to install Edge Manager in disconnected mode.

Some of the requirements of Edge Manager can be satisfied by the existing RPM package and container image mirrors in the ROL classroom, but some of them require internet access, a valid Red Hat login, and Red Hat subscription entitlements.

If this is your first time using a ROL classroom, please refer to the previous course for a gentler introduction to the classroom environment and to tasks such as installing and configuring Red Hat Edge Manager.

Here the focus is on quickly having the environment ready for the tasks of this course, by re-creating some of the outcomes from the previous course. If you are proceeding directly after completing the previous course, without destroying and re-creating its classroom environment, you will skip most steps here.

  1. On your development machine, download the sample code for this course.

    1. Using a shell on your development machine (which is the workstation VM), ensure you are on your home directory. All labs start from there, but they will use different work directories, so this course starts all labs from the same reference point.

      $ cd

    2. Verify if you already have the the samples repository.

      $ ls rhde-rhem-samples
LICENSE  README.md  antora.yml  config  enroll  modules  webapp

    3. If you do, enter the samples repository and update it, just in case.

      $ cd rhde-rhem-samples
$ git pull
Already up to date.
$ cd

    4. If you do not.

      $ ls rhde-rhem-samples
ls: cannot access 'rhde-rhem-samples': No such file or directory

      Then clone the course samples repository.

      $ git clone https://github.com/RedHatQuickCourses/rhde-rhem-samples.git
Cloning into 'rhde-rhem-samples'...
...

  2. Install tools for managing containers and VMs on your development machine.

    1. Install the container-tools meta-package. Altough the workstation VM has Podman preinstalled, you will need the full suite of container tools in this course.

      $ sudo dnf install skopeo buildah
...
Complete!

    2. Install the libvirt tools and enable its QEMU socket service.

      $ sudo dnf install qemu-kvm libvirt virt-install virt-viewer
...
Complete!
$ sudo systemctl enable virtqemud.socket --now
Created symlink /etc/systemd/system/multi-user.target.wants/virtqemud.socket → /usr/lib/systemd/system/virtqemud.socket.

    3. Check that your unprivileged user can connect using the libvirt session interface.

      $ virsh uri
qemu:///session
$ virsh nodeinfo
CPU model:           x86_64
...

  3. Configure your development machine to access RPM packages and container images from Red Hat, over the internet.

    1. Register your development machine with the Red Hat subscription manager.

      If you are using the upstream Flight Control packages, you can use the login from a free Red Hat Developer subscription for individuals.

      The workstation VM is preconfigured with access to a private mirror containing RHEL 10 packages, but it will need RHEL 9 packages to build bootc container images for edge devices that will be managed by Edge Manager. 
      $ sudo subscription-manager register
...
The registered system name is: workstation

    2. Log in on the Red Hat container registry.

      Use the same Red Hat login that you used with subscription manager.

      $ podman login registry.redhat.io
...
Login Succeeded!

    3. Verify that you can access the bootc image builder container image. You may get a different hash, because the container image was updated since these instructions were written.

      $ skopeo inspect --format '{{.Digest}}' docker://registry.redhat.io/rhel9/bootc-image-builder:9.6
sha256:f5e1860fae45c9d01fb612fcfad6c1d3a93e9ea4533bf01ea1c4d47ae2226580

    4. Download the bootc image builder to the container storage of the root user.

      You will run bootc image builder as root, so you must log in again on the Red Hat container registry.

      $ sudo podman login registry.redhat.io
...
Login Succeeded!
$ podman pull docker://registry.redhat.io/rhel9/bootc-image-builder:9.6
...
Storing signatures
a93aa271855242ac292133fb261c2132dd88859abb7edc29fb5681d30db422f2

  4. Install the Edge Manager services on your server machine.

    1. Open an SSH session or a terminal on your server machine. Make sure your current shell is on the right machine before you proceed.

      $ hostname
servera

    2. Install the container tools on your server machine.

      $ sudo dnf install podman skopeo
...
Complete!

    3. Enable the Flight Control repository from EPEL.

      $ sudo dnf config-manager --add-repo https://rpm.flightctl.io/flightctl-epel.repo
Adding repo from: https://rpm.flightctl.io/flightctl-epel.repo
      There is no need to register servera because the Flight Control services package contains no dependencies other than a container engine (Podman) and the classroom environment contains a mirror of the RHEL 10 packages, which the sererva machine is preconfigured to use.

    4. Install the Edge Manager services.

      $ sudo dnf install -y flightctl-services-1.0.2
...
Complete!
      If you want to try the current latest release from the upstream project, remove the version component -1.0.2 from the package flightctl-services in the command above.

    5. Start the Edge Manager services.

      $ sudo systemctl enable --now flightctl.target
Created symlink '/etc/systemd/system/multi-user.target.wants/flightctl.target' → '/usr/lib/systemd/system/flightctl.target'.

    7. If you experience errors, or it seems that the Edge Manager services are taking too long to start, refer to the previous course for troubleshooting hints.

  5. For simplicity, configure local users for the Edge Manager services, on the PAM issuer container.

    1. Create groups which correspond to the admin, operator, and viewer roles.

      $ sudo podman exec -i flightctl-pam-issuer groupadd flightctl-admin
$ sudo podman exec -i flightctl-pam-issuer groupadd flightctl-operator
$ sudo podman exec -i flightctl-pam-issuer groupadd flightctl-viewer

    2. Create a user named student and grant it the operator role.

      $ sudo podman exec flightctl-pam-issuer adduser student
$ sudo podman exec -i flightctl-pam-issuer sh -c 'echo "student:student" | chpasswd'
$ sudo podman exec -i flightctl-pam-issuer usermod -aG flightctl-operator student

    3. Create a user named admin and grant it the admin role.

      $ sudo podman exec flightctl-pam-issuer adduser admin
$ sudo podman exec -i flightctl-pam-issuer sh -c 'echo "admin:redhat" | chpasswd'
$ sudo podman exec -i flightctl-pam-issuer usermod -aG flightctl-admin admin

    4. Verify you have the required users and groups on the PAM issuer container.

      $ sudo podman exec -i flightctl-pam-issuer groups student
student : student flightctl-operator
$ sudo podman exec -i flightctl-pam-issuer groups admin
admin : admin flightctl-admin

  6. Install the Edge Manager CLI on your development machine

    1. Make sure your current shell is on the right machine.

      $ hostname
workstation

    2. Enable the flight repository from EPEL and install its CLI package.

      $ sudo dnf config-manager --add-repo https://rpm.flightctl.io/flightctl-epel.repo
Adding repo from: https://rpm.flightctl.io/flightctl-epel.repo
$ sudo dnf install flightctl-cli
...
Complete!

    3. Verify that the flightctl command is in your command PATH.

      $ flightctl version
Client Version: v1.0.0
Server Version: Could not read server version
You must log in to view the server version. Please use the 'login' command to authenticate before proceeding

    4. Copy the self-signed certificate of the Edge Manager server and add it to the system’s trusted CA set.

      $ scp servera:/etc/flightctl/pki/ca-bundle.crt ~
ca-bundle.crt             100% 1222   128.6KB/s   00:00
$ sudo cp ca-bundle.crt /etc/pki/ca-trust/source/anchors/
$ sudo update-ca-trust extract

    5. Log in on the Edge Manager server.

      $ flightctl login -u admin -p redhat https://servera.lab.example.com:3443
Auto-selected organization: 00000000-0000-0000-0000-000000000000 Default
Login successful.

    6. Verify that the CLI can now get the server’s version, and that there are no managed devices yet.

      $ flightctl version
Client Version: v1.0.0
Server Version: v1.0.0
$ flightctl get device
NAME    ALIAS   OWNER   SYSTEM  UPDATED APPLICATIONS
