Lab: Configure Devices Using Git Repositories

Estimated reading time: 5 minutes.

Objective

Configure multiple devies, which belong to fleets, from files stored in a git repository.

Work In Progress

Before you begin

You need a development machine running RHEL, with enough capacity to run a few local VMs and a custom installer ISO used to provision new local VMs.

You also need a server machine running RHEL, which is already configured as an Edge Manager server.

Both your development machine and server machine were configured by performing the first lab.

If you are using the course classroom, your development machine is the workstation VM. Log in as the user student with password student. From that machine, you may start SSH sessions to the servera VM, which is your server machine, using the same user. Alternatively, you can open a shell or a console directly on the servera VM.

This lab does not require the outcomes of the previous lab. You could perform just the first lab and skip to here. The example outputs of commands assume that you are performing all labs sequentially, in the same environment. If you skipped a lab, your output may display different sets of VMs, devices, and fleets, but it shouldn’t affect the intended outcomes of this lab.

Instructions

High-level summary of what you will perform in this lab, but more detailed than the objective.

The classroom environment has an issue which requires setting SELinux to permissive mode. This is something Red Hat do NOT advises doing to any production system, including developer machines and CI/CD servers.

On your development machine, perform the following before you attempt any lab of this course.

$ sudo setenforce Permissive

Note tat SELinux is still in enforcing mode on your server machine and also on all test VMs which stand in for managed devices. Only your development machine needs SELinux set to permissive mode.

  1. Verify that you have the prerequisites from the first lab. If any of the prerequisites are missing, please return to the first lab and ensure that you did not skip any step.

    1. Verify that you have a clone of the course samples repository.

      $ cd
$ ls rhde-rhem-samples
antora.yml  config  enroll ...

    2. Verify that you have two local VMs.

      $ virsh list --all
 Id   Name     State
------------------------
 1    edge-1   running
 2    edge-2   running
 3    edge-3   running

    3. If your VMs are not running, start them, but ensuring they are booting as a device that has been powered on, without reusing any saved state.

      $ virsh list --all
 Id   Name     State
-------------------------
 -    edge-1   shut off
 -    edge-2   shut off
 -    edge-3   shut off
      $ virsh start edge-1 --force-boot
Domain 'edge-1' started
# repeat for the remaining VMs

    4. Give your local VMs a few moments to finish boot. Then, log in on Edge Manager as a non-administrator and verify that there are two managed devices, which are on-line and up-to-date.

      $ flightctl login -u student -p student https://servera.lab.example.com:3443
Auto-selected organization: 00000000-0000-0000-0000-000000000000 Default
Login successful.
      $ flightctl get device
NAME                                                    ALIAS   OWNER            SYSTEM  UPDATED         APPLICATIONS
mpr39vjcj5fup095de4pqnld6h4snt2ud79g74p7spv5i00jjid0    edge-3  Fleet/warehouse  Online  UpToDate        NoApplications
g7ombcqk46tqq458j9uju454441mf1lgt9qqqva8ti0fnvosm57g    edge-2  Fleet/store      Online  UpToDate        NoApplications
1u63hvsgtua9tjjbmla9bgh5h2s77cb8esepphnf68m3ocf8qfng    edge-1  <none>           Online  UpToDate        NoApplications

    5. If you devices keep displaying as off-line for too long, it might be related to clock skew. In that case, stop each of your local VMs and return to the beginning of this lab.

      Clock skew prevents a device from synchronizing with Edge Manager, and is known to happen if your ROLE classroom is stopped without first shutting down local VMs on your develoment machine and later your VMs are restarted from saved state. 
      $ virsh destroy edge-1
Domain 'edge-1' destroyed
# repeat for the remaining VMs

  2. Configure a repository source, using the web UI.

    1. On your development machine, start a web browser and open https://servera.lab.example.com. Log in on Edge Manager as student using the student password. On the left pane, click Repositories. It should display a page which states "No repositories yet".

    2. Click Create repository. Name your repository as samples and, for the Repository URL, type https://github.com/RedHatQuickCourses/rhde-rhem-samples.git which is the URL of the samples repository of this course.

    3. Unckeck Use resource syncs and click Create repository.

    4. The repository details page shows the repository with a status of Sync pending. After a few monents the status of the repository should change to Accessible.

      If you experience any errors, click the status icons for a descriptive message of the error and make any required fix.

  3. Explore the contents of the samples repository.

    1. Still on the repository details page, click on the value of the Url, that is, click on https://github.com/RedHatQuickCourses/rhde-rhem-samples.git. It opens a new browser tab on GitHub.

    2. Click pos/etc and see it contains a single file named motd. Open the file and view its contents. Then return to the browser tab with the Edge Manager web UI.

  4. Create a fleet which refers to the repository source.

    1. On the left pane, click Fleets and then click Create fleet. Name your new fleet as pos and, under Device selector, click on Add label. Type role=pos as the device selector, and press Tab to leave the text box. Ignore the warning that "There are no devices matching these labels" and click Next.

    2. Under Host configuration (files), click Add configuration and type store on the Source name field. Select Git configuration as the Source type field and select samples as the Repository.

    3. Type main as the Branch/tag/commit field, and /pos as the Path.

    4. Click Next until you reach the end of the Create fleet assistant and click Create fleet. You should get a details page for a fleet in the Valid state and with no devices.

  5. Add a device to your new fleet.

    1. On the left pane, click Devices and click on edge-1, which should be a member of no fleet.

    2. On the device details page, click Add label and type role=pos, then press Tab.

    3. Verify that the details page now display the Fleet name as pos and scroll down to see the Update status heading. Wait until the status change to Up-to-Date.

    4. Click the Terminal tab and verify that the /etc/motd file has been changed.

      $ cat /etc/motd
This is a point-of-sale terminal.
Its configurations ate set by Red Hat Edge Manager.
