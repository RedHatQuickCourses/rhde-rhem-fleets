Lab: Configure and Manage Device Fleets

Estimated reading time: 5 minutes.

Objective

Configure multiple device fleets and assign devices to them using fleet-level configurations.

Work In Progress

Before you begin

Describe requirements, such as customer portal accounts, Red Hat Developer free sub, already configured machines, access to container registries, etc.

Instructions

High-level summary of what you will perform in this lab, but more detailed than the objective.

The classroom environment has an issue which requires setting SELinux to permissive mode. This is something Red Hat do NOT advises doing to any production system, including developer machines and CI/CD servers.

On your development machine, perform the following before you attempt any lab of this course.

$ sudo setenforce Permissive

Note tat SELinux is still in enforcing mode on your server machine and also on all test VMs which stand in for managed devices. Only your development machine needs SELinux set to permissive mode.

  1. Verify that you have the prerequisites from the previous lab. If any of the prerequisites are missing, please return to the previous lab and ensure that you did not skip any step.

    1. Verify that you have a clone of the course samples repository.

      $ cd
$ ls rhde-rhem-samples
antora.yml  config  enroll ...

    2. Verify that you have two local VMs.

      $ virsh list --all
 Id   Name     State
------------------------
 1    edge-1   running
 2    edge-2   running

    3. If your VMs are not running, start them, but ensuring they are booting as a device that has been powered on, without reusing any saved state.

      $ virsh list --all
 Id   Name     State
-------------------------
 -    edge-1   shut off
 -    edge-2   shut off
      $ virsh start edge-1 --force-boot
Domain 'edge-1' started
$ virsh start edge-2 --force-boot
Domain 'edge-2' started

    4. Give your local VMs a few moments to finish boot. Then, log in on Edge Manager as a non-administrator and verify that there are two managed devices, which are on-line and up-to-date.

      $ flightctl login -u student -p student https://servera.lab.example.com:3443
Auto-selected organization: 00000000-0000-0000-0000-000000000000 Default
Login successful.
$ flightctl get device

    5. If you devices keep displaying as off-line for too long, it might be related to clock skew. In that case, stop each of your local VMs and return to the beginning of this lab.

      Clock skew prevents a device from synchronizing with Edge Manager, and is known to happen if your ROLE classroom is stopped without first shutting down local VMs on your develoment machine and later your VMs are restarted from saved state. 
      $ virsh destroy edge-1
Domain 'edge-1' destroyed
$ virsh destroy edge-2
Domain 'edge-2' destroyed

  2. Create a device fleet, using the web UI. The process is very similar to editting a device configuration, if you remember the activity from the first course.

    You will configure your fleet with a device template that sets two configuration files, using the inline configuration provider: A pre-login banner, and a lifecycle hook to enable login using the serial console.

    1. On your development machine, start a web browser and open https://servera.lab.example.com. Log in on Edge Manager as student using the student password. On the left pane, click Fleets. It should display a page which states "No fleets yet".

    2. Click Create fleet. Name your new fleet as store and, under Device selector, click on Add label. Type location=store as the device selector, and press Tab to leave the text box. Ignore the warning that "There are no devices matching these labels" and click Next.

    3. Under Host configuration (files), click Add configuration and type store on the Source name field. Select Inline configuration as the Source type field.

    4. Under File 1, type /etc/issue.d/warning.issue as the File path field, and type the following on the Content field:

      This is managed device {{ .metadata.labels.alias }}
Access by non-authorized personnel is strictly forbidden.

      Also ensure that there is a blank line at the end of the multi-line text box.

    5. Scroll down and click Add file to create File 2. Type /etc/flightctl/hooks.d/afterupdating/enable-serial-console.yaml as the File path field, and type the following on the Content field:

      - run: /usr/bin/systemctl enable serial-getty@ttyS0.service --now

    6. Click Next until you reach the end of the Create fleet assistant and click Create fleet. You should get a details page for a fleet in the Valid state and with no devices.

  3. Alter the labels on the first managed device so it joins the fleet and verify it got the fleet configuration.

    1. Switch to a terminal and attempt to open the serial console of your local VM. It does not display a log in prompt, no matter which keys you press. Your only alternative is dettaching from the VM console using Ctrl+].

      $ virsh console edge-1
Connected to domain 'edge-1'
Escape character is ^] (Ctrl + ])

    2. Back to your web browser, click Devices on the left pane. Then click on the menu icon (three vertical dots) for the edge-1 managed device and select Edit device configurations.

    3. Click on Add label and type location=store on the text box. Press Tab to close the text box and notice that the page displays a green check mark under Fleet name, acknowledging that the new label makes the device a member of the store fleet.

    4. Click Next until you reach the last page of the assistant, and click save.

    5. Scroll down and notice that the Update status is Out-of-date. Wait until it changes to Up-to-date.

    6. Switch to a terminal and attempt again to open a terminal. You may have to press Enter a few times to get a log in prompt. After you get the prompt, press Ctrl+D to reset the log in process and view the banner messages.

      You should see the standard banner from Edge Manager, which displays a QR code used to enroll or manage the device, and the warning that the fleet configuration added.

      You do not need to log in. You can press Ctrl+] to dettach from the virtual console, after confirming the warning banner is displayed by the device.

      $ virsh console edge-1
