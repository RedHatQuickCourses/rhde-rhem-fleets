Lab: Troubleshoot Device and Fleet Issues

Estimated reading time: 12 minutes.

Objective

Practice troubleshooting by creating scenarios with health issues, then extract diagnostic information using RHEM tools.

Pending Review

Before you begin

You need a development machine running RHEL, and hosting a few local VMs which stand in for managed devices. These local VMs are already provisioned and enrolled in Edge Manager.

You also need a server machine running RHEL, which is already configured as an Edge Manager server.

Both your development machine and server machine were configured by performing the first lab.

If you are using the course classroom, your development machine is the workstation VM. Log in as the user student with password student. From that machine, you may start SSH sessions to the servera VM, which is your server machine, using the same user. Alternatively, you can open a shell or a console directly on the servera VM.

This lab does not require the outcomes of any of the previous labs, you could perform just the first lab and skip to here. The example outputs of commands assume that you are performing all labs sequentially, in the same environment. If you skipped any of previous labs, or if you had to destroy and recrete your enviromnent, your actual outputs may display different sets of VMs, devices, and fleets, but that should not affect the expected outcomes of this lab.

Instructions

You will configure a fleet with two devices and a disk utilization monitor. Then you will simulate a disk full condition, on one of the devices, and detect the condition using Edge Manager. Finally, you will resolve the disk condition and verify that Edge Manager reports the device back to healthy.

The classroom environment has an issue which requires setting SELinux to permissive mode. This is something Red Hat do NOT advises doing to any production system, including developer machines and CI/CD servers.

On your development machine, perform the following before you attempt any lab of this course.

$ sudo setenforce Permissive

Note tat SELinux is still in enforcing mode on your server machine and also on all test VMs which stand in for managed devices. Only your development machine needs SELinux set to permissive mode.

  3. Add a device monitor to the fleet, using the provided manifest.

    1. Create a temporary working directory, and copy example files to it.

      $ mkdir temp-monitor
$ cd temp-monitor
$ cp -r ../rhde-rhem-samples/monitor/* .

    2. Review the new manifest for the warehouse fleet. It adds a disk space monitor, which trigger alerts when the disk is 50% and 80% full.

      the sampling interval and durations used in the example may not be suitable for production environments, but are intended to trigger events very quickly, so this lab doesn’t take too long to complete.
      In image mode systems, the root (/) directory is a bind mount. The real root disk is mounted on the '/sysroot' directory. Your test VMs do not set any other disk partitions, so /var and /etc are in the same root disk. The only other disk partition is the /boot filesystem, which we can ignore for a disk monitor. 
      $ cat disk-monitor.yaml
apiVersion: flightctl.io/v1beta1
kind: Fleet
metadata:
  name: warehouse
spec:
  selector:
    matchLabels:
      location: warehouse
  template:
    spec:
      applications: []
      config:
      - inline:
        - content: |-
            export PS1="managed device: {{ .metadata.labels.alias }}\$ "

          path: /etc/profile.d/managed-device.sh
        name: ps1
      resources:
      - monitorType: Disk
        samplingInterval: 5s
        path: /sysroot
        alertRules:
        - severity: Warning
          duration: 1m          
          percentage: 50
          description: Disk is over 50% full for over 1min.
        - severity: Critical
          duration: 3m
          percentage: 80
          description: Disk is over 80% full over 3min.

    3. Apply the modifications to the fleet.

      $ flightctl apply -f disk-monitor.yaml
disk-monitor.yaml: applying fleet/warehouse: 200 OK
